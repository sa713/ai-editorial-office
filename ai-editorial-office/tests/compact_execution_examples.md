# Compact Execution Synthetic Examples

These examples are synthetic. They are not task materials and do not describe
real clients, employees, messages, systems, or source documents.

## Example 1 - Low-risk Messenger Post

Scenario: create a short internal messenger reminder for a fictional team
retro. No factual claims, product claims, external publication, or sensitive
content.

Risk mode: `low-risk`

Execution profile: `compact`

Minimal file set:

- `brief.md`
- `task-manifest.md`
- `status.md`
- `orchestration_plan.md`
- `draft.md`
- `review.md`
- `final.md`
- `final_decision.md`

Optional artifacts intentionally omitted:

- `research.md`
- `sources.md`
- `claims_table.md`
- `qa-checklist.md`
- `review-summary.md`
- `finalization-notes.md`

Rationale: the copy is low-risk and source-free. Review still checks scope,
tone, independence, and readiness before finalization.

## Example 3 - High-governance External Communication

Scenario: prepare a synthetic external announcement for a fictional product
change. The message includes product behavior claims, dates, user-impacting
language, and likely human approval.

Risk mode: `high-governance`

Execution profile: `expanded`

Expanded file set:

- `brief.md`
- `task-manifest.md`
- `status.md`
- `orchestration_plan.md`
- `research.md`
- `sources.md`
- `facts.md`
- `claims_table.md`
- `draft.md`
- `claims-used.md`
- required handoff files
- `review.md`
- `qa-checklist.md`
- `review-summary.md`, if a separate governance transfer is needed
- `final.md`
- `finalization-notes.md`
- `finalization-checklist.md`
- `approval.md`, if human approval is required
- `final_decision.md`

Why compact is insufficient: review needs source and claim traceability,
approval state, product-behavior evidence, and explicit governance closure.
Optional artifacts are still not automatic; they are created only when required
by the selected pipeline, high-governance risk, downstream governance, or
traceability.

# Writer Notes

## Source Use

Primary source artifacts:

- `sources.md`
- `research.md`
- `claims_table.md`

The Framework uses all 55 KB records plus KB model documents. Criteria were
drafted from `claims_table.md`.

## Writing Choices

- Split the Framework into multiple files for repeat use and reviewability.
- Put area-level mature/problem/anti-pattern signs in `02-audit-areas.md`.
- Put criterion-level rationale/evidence/questions in `03-assessment-criteria.md`.
- Keep KB gaps separate in `08-kb-gaps.md`.
- Use a custom maturity model to avoid single-metric and ladder-chasing risks.

## Caveats

- Security/AI risk criteria are high-level because KB lacks local control
  mapping.
- AI-agent criteria need refresh before each audit cycle because records are
  Evolving or Under Evaluation.
- Platform portal is not required because KB rejects internal developer portal
  for current context.
- BRD, Product Analyst, Validator, and Historian are gap-only topics because
  they are not canonical.

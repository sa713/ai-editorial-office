# Writer Notes

## role

Produced as `writer_agent` from the approved compact brief and source file.

## source use

The main source was `Roadmap.md`. The source contains three layers:

- concept and diagnosis: practical workshop, not portal or link base;
- operational formats, artifacts, mechanics and light functions;
- implementation timing, resource hints, risks and "what not to do" sections.

The first two layers were preserved and reorganized. The third layer was used only where it helped explain value, degradation risks or discussion questions. Calendar timing, resource estimates, KPI language, implementation roadmap, staffing and separate "what not to do" framing were intentionally excluded from the main deliverables.

## structure decisions

- `leadership_ideas_pack.md` is the main leadership-facing document. It explains the concept, value, operational loop, broad set of formats, artifacts and scenarios.
- `community_entities_map.md` is structural and table-first. It maps activities, artifacts, mechanics, light functions and connections.
- `portal_content_ideas.md` describes content blocks and page logic without UI design, UX button texts, technical architecture or integrations.

## preserved source idea groups

- Practical workshop framing.
- Portal/chat insufficiency.
- Minimal loop: input -> review/discussion -> fixation -> artifact -> publication -> reuse.
- Activities: `vibe clinic`, `vibecode challenge`, `workflow demo`, `office hours`, pair experiments, `mini-jams`, `live debugging sessions`, case reviews, `prompt review sessions`.
- Artifacts: case cards, workflow cards, `anti-pattern card`, "before/after", `workflow library`, `prompt templates`, `troubleshooting notes`, `digest`, `FAQ`, `onboarding path`, "where to start" block.
- Mechanics: case intake, question intake, challenge formation, artifact publication, rhythm, avoiding a dead catalog.
- Light functions: clinic host, case author, artifact editor, newcomer, experienced participant, workflow contributor, `challenge host`, light-rhythm coordinator.

## exclusions

- No presentation or slide structure.
- No `.pptx`.
- No speaker notes.
- No implementation roadmap.
- No resource, budget, staffing or workload estimates.
- No KPI or metrics.
- No technical specification.
- No UI mockup, UI architecture or UX interface copy.
- No separate document about "what not to do".
- No changes outside the task folder.

## review focus requested

Review should check:

- deliverables are self-contained and leadership-ready;
- broad source coverage is preserved;
- prohibited implementation, KPI, resource, UI and technical layers are absent from main deliverables;
- required terms remain unchanged;
- portal is positioned as support for a living community, not a link archive;
- review-gate and task-folder constraints are preserved.

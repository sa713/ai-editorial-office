# Vibe Coding Community: карта сущностей

## 1. Общая схема

`Vibe Coding Community` можно описать как набор связанных сущностей:

- активности, где люди встречаются и разбирают практику;
- артефакты, которые остаются после активностей;
- механики, которые превращают вопросы в материалы;
- лёгкие функции, которые помогают поддерживать ритм.

Это не оргструктура и не governance model. Это карта живой практики сообщества.

## 2. Активности

| Сущность | Что это | Для кого | Какую проблему решает | Что остаётся после |
| --- | --- | --- | --- | --- |
| `vibe clinic` | Короткий регулярный разбор одного вопроса, кейса, prompt chain, workflow или неудачного опыта | Новички, разработчики, опытные участники, авторы кейсов | Даёт сообществу пульс и превращает сырые вопросы в практические выводы | Карточка кейса, `troubleshooting notes`, `FAQ` item, тема для следующего разбора, иногда `anti-pattern card` |
| `vibecode challenge` | Небольшая практическая задача, которую участники решают с AI-инструментами и затем сравнивают подходы | Участники, которым полезно увидеть разные стратегии на одной задаче | Показывает, что важно не только решение, но и prompts, контекст, проверки и ошибки | Подборка подходов, удачные prompts, список проверок, `anti-pattern card`, «до / после», материал для `digest` |
| `workflow demo` | Короткий показ одного рабочего приёма с AI-инструментом | Опытные участники и те, кто ищет переносимые способы работы | Позволяет делиться практикой без большого доклада | Карточка workflow, пример `prompt templates`, ограничения, короткий конспект |
| `office hours` | Открытое окно для вопросов новичков и людей, которые застряли | Новички, участники с первыми рабочими вопросами | Снижает барьер входа и помогает задавать простые вопросы без стыда | `FAQ` items, уточнения для `onboarding path`, темы для `vibe clinic` |
| Парные эксперименты | Неформальная пара на 30-60 минут для первого применения AI на задаче участника | Участники, которым нужен безопасный первый шаг | Снижает страх первого применения и помогает начать с реальной задачи | Короткая заметка, возможная карточка кейса, вопрос для `vibe clinic` |
| `mini-jams` | Совместная короткая сессия, где участники пробуют разные prompts, инструменты или подходы к маленькой проблеме | Участники, которым полезно быстро сравнить варианты | Исследует пространство решений без большого challenge | Prompt variants, выводы, `prompt templates`, `anti-pattern card` |
| `live debugging sessions` | Живой разбор проблемы с AI-инструментом: дефект, ошибка, странный ответ, неверная гипотеза | Разработчики и участники, которые хотят видеть процесс диагностики | Показывает, как проверять гипотезы и не доверять первому ответу | `troubleshooting notes`, список проверок, `anti-pattern card`, кейс |
| Кейс-разборы | Разбор завершённого опыта применения AI-инструмента | Авторы кейсов, участники, которые ищут примеры из похожей среды | Превращает опыт в память сообщества | Карточка кейса, workflow, `prompt templates`, `anti-pattern card`, материал для `digest` |
| `prompt review sessions` | Разбор prompts или prompt chains с улучшением точности, безопасности и проверяемости | Участники, которым нужна быстрая прикладная польза | Улучшает постановку задачи на конкретных формулировках | Улучшенный prompt, объяснение изменений, `prompt templates`, `anti-pattern card` |

## 3. Артефакты

| Сущность | Что это | Откуда появляется | Где используется дальше |
| --- | --- | --- | --- |
| Карточка кейса | Короткое описание реального применения AI-инструмента в рабочей задаче | `vibe clinic`, кейс-разбор, `vibecode challenge`, парный эксперимент, `office hours` | База кейсов, `digest`, темы для новых разборов, ссылки в `FAQ` |
| Карточка workflow | Повторяемый способ работы с AI-инструментом для конкретного типа задач | `workflow demo`, кейс, `prompt review sessions`, `mini-jams` | `workflow library`, onboarding, ответы на вопросы, связанные кейсы |
| `anti-pattern card` | Короткий разбор типичной ошибки и альтернативного подхода | `vibe clinic`, `vibecode challenge`, `prompt review sessions`, `live debugging sessions` | Onboarding, `FAQ`, `digest`, предупреждения рядом с workflow |
| «До / после» | Наглядное сравнение работы до и после применения AI-инструмента | `vibecode challenge`, кейс-разбор, успешный workflow | Объяснение практической ценности, `digest`, обсуждения с руководством |
| `workflow library` | Библиотека проверенных workflow, организованная по задачам | Из карточек workflow и связанных кейсов | Навигация по практикам, onboarding, ответы на рабочие вопросы |
| `prompt templates` | Шаблоны prompts с контекстом, полями для замены и проверками | `prompt review sessions`, `workflow demo`, `mini-jams`, кейсы | Workflow, onboarding, `FAQ`, повторное применение участниками |
| `troubleshooting notes` | Короткие заметки по диагностике проблем с AI-инструментами или AI-generated результатами | `vibe clinic`, `live debugging sessions`, `office hours` | Ответы на повторяющиеся проблемы, `FAQ`, база практик |
| `digest` | Краткий обзор практик и выводов за период | Из свежих кейсов, workflow, prompts, anti-patterns и открытых вопросов | Возвращает в контекст тех, кто не был на встречах; анонсирует новые материалы |
| `FAQ` | Повторяющиеся вопросы с короткими ответами и ссылками на практические материалы | `office hours`, `vibe clinic`, чат | Onboarding, снижение повторной нагрузки, быстрый вход |
| `onboarding path` | Короткий маршрут для нового участника | Из стартовых материалов, `FAQ`, office hours, кейсов | Первый вход в сообщество, навигация к действиям |
| Блок «с чего начать» | Четыре простых входа: попробовать AI, посмотреть кейсы, задать вопрос, поделиться workflow | Портал, onboarding, регулярные форматы | Снижает потерю участников на первом шаге |

## 4. Механики

| Механика | Зачем нужна | Как работает | Что производит |
| --- | --- | --- | --- |
| Как появляются новые кейсы | Чтобы кейсы не зависели от отдельной просьбы «напишите материал» | После активности ведущий задаёт вопрос: есть ли здесь кейс, который стоит сохранить; автор получает короткий шаблон и помощь с упаковкой | Карточки кейсов, workflow, вопросы для новых разборов |
| Как участники приносят вопросы | Чтобы вход был лёгким и вопросы не терялись | Один понятный вход через тред, форму или `office hours`; минимальный шаблон: что хочу сделать, где застрял, какой инструмент использую, можно ли разбирать публично, нужна ли помощь один на один | Очередь тем для `vibe clinic`, `office hours`, `FAQ` |
| Как формируется `vibecode challenge` | Чтобы задача была рабочей, безопасной и посильной | `challenge host` выбирает небольшую задачу с понятным результатом, без чувствительных данных, с возможностью сравнить подходы и проверить решение | Материал для `prompt templates`, `anti-pattern card`, «до / после», `digest` |
| Как артефакты попадают в базу | Чтобы опыт не оставался в чате и записях встреч | После активности выбирается тип артефакта, создаётся короткий черновик, автор быстро проверяет фактуру, материал публикуется и анонсируется | База практик, связанные карточки, свежие материалы для портала |
| Как поддерживается регулярность | Чтобы у сообщества был следующий понятный шаг без тяжёлой программы | Ближайшие активности выбираются из очереди вопросов, кейсов и workflow; важнее полезность, чем плотность расписания | Пульс сообщества, свежие материалы, понятный вход |
| Как не допустить мёртвого каталога | Чтобы портал не стал музеем намерений | Разделы открываются, когда есть материалы; устаревшее убирается или архивируется; полезные workflow и свежие кейсы поднимаются на видное место | Живая страница, актуальная база, меньше пустых разделов |

## 5. Лёгкие функции внутри сообщества

| Функция | Что делает | Почему это не должность |
| --- | --- | --- |
| Ведущий `clinic` | Выбирает вопрос, уточняет вводные, держит рамку разбора, помогает сформулировать выводы | Это функция на конкретный разбор; её могут брать разные участники |
| Автор кейса | Приносит реальный опыт применения AI-инструмента и помогает проверить фактуру карточки | Автору не нужно быть спикером или экспертом; достаточно одного опыта |
| Редактор артефактов | Помогает превратить разговоры в короткие материалы: кейсы, workflow, `FAQ`, `digest` | Это лёгкая функция упаковки, а не владелец всего знания сообщества |
| Новичок | Приносит первые вопросы и показывает, где вход в сообщество непонятен | Это состояние участника, а не роль в системе |
| Опытный участник | Показывает приёмы, помогает на `office hours`, участвует в review prompts, предлагает workflow | Участие может быть маленьким и нерегулярным; человек не становится официальным экспертом по всем вопросам |
| Человек, который приносит workflow | Показывает один повторяемый способ работы и помогает оформить карточку | Не нужно вести формат постоянно; достаточно одного полезного приёма |
| `challenge host` | Готовит задачу для `vibecode challenge`, собирает подходы и ведёт разбор | Это функция для конкретного challenge, а не постоянная должность |
| Координатор лёгкого ритма | Следит за ближайшими активностями, темами в очереди и актуальностью блока «что происходит сейчас» | Это минимальная координация, не управление сообществом и не отчётная роль |

## 6. Связи между сущностями

- `vibe clinic` -> карточка кейса / `troubleshooting notes` / `FAQ` item.
- `vibecode challenge` -> `prompt templates` / `anti-pattern card` / «до / после» / `digest`.
- `workflow demo` -> карточка workflow / `prompt templates`.
- `office hours` -> `FAQ` / `onboarding path` / темы для `vibe clinic`.
- Парные эксперименты -> короткая заметка / кейс / вопрос для `vibe clinic`.
- `mini-jams` -> prompt variants / `prompt templates` / `anti-pattern card`.
- `live debugging sessions` -> `troubleshooting notes` / список проверок / `anti-pattern card`.
- Кейс-разборы -> карточка кейса / workflow / `digest`.
- `prompt review sessions` -> улучшенный prompt / `prompt templates` / `anti-pattern card`.

## 7. Минимальная операционная петля

1. **Вход.** Участник приносит вопрос, кейс, workflow или проблему.
2. **Разбор.** Сообщество разбирает это в коротком формате.
3. **Фиксация.** Ведущий или редактор выделяет переносимые выводы.
4. **Артефакт.** Вывод превращается в маленький материал.
5. **Публикация.** Артефакт попадает на страницу и анонсируется.
6. **Повторное использование.** Другой участник применяет материал и приносит уточнение, вопрос или новый кейс.

Петля работает, если:

- вход лёгкий;
- разбор короткий;
- артефакт маленький;
- публикация быстрая;
- материалы связаны с реальными задачами;
- участники видят, что их вклад не исчезает.

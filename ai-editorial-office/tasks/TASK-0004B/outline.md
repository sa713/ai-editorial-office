# Outline

## Revised Instruction Structure

1. `Что такое Биржа задач`
   - Purpose of the tool.
   - Pilot limitation on АС Taska.
   - Main available actions.

2. `Выберите свой путь`
   - Three reader routes: Автор, Исполнитель, Идея.
   - One-line description of each route.

3. `Если вы публикуете задачу`
   - When to use task.
   - Create card.
   - Wait for moderation.
   - Choose executor.
   - Agree result and deadline.
   - Accept result or return for revision.

4. `Если вы хотите выполнить задачу`
   - Find task in `To Do`.
   - Leave comment.
   - Wait for assignment.
   - Agree result and deadline.
   - Report completion and revise if needed.

5. `Если вы подаёте идею`
   - When to use idea.
   - What fields to fill.
   - Deadline not filled.
   - Moderation outcomes.
   - Track progress in card.

6. `Поля, ограничения и карточки`
   - Shared field rules.
   - What can be attached.
   - What stays empty.
   - Subtasks are not created.
   - Comments can clarify details.

7. `Статусы и кто делает следующий шаг`
   - `Backlog`, `To Do`, `Done`.
   - Who acts in each state.
   - `Мои задачи`.

8. `Спорные ситуации и контакты`
   - Typical disputes.
   - What to include in escalation.
   - Curators.

## Writing Guardrails

- Keep the instruction operational, not promotional.
- Use source terms: Автор, Исполнитель, Модераторы, Кураторы, Задача, Идея.
- Keep disputed or uncertain source fragments out: the draft had an unresolved `Инициатива ?`, so do not introduce the term.
- Avoid a duplicated full process narrative before role paths.

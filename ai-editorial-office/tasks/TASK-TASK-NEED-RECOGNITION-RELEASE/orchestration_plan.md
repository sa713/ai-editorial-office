## editorial decision frame

- Chosen route: research authoritative classification and intake practice;
  separate recognition signals from existing decisions; implement one compact
  advisory view before Chief Editor routing using existing task artifacts,
  roles, capability registry, Domain Pack activation, evidence, and review.
- Why this route serves the task: it improves routing evidence without creating
  a parallel router or transferring decision authority.
- Alternatives considered:
  - Add an automatic intent classifier or keyword rules.
    - Rejected: it would make hidden route decisions and overfit surface terms.
  - Add a Task Router role, pipeline, or gate.
    - Rejected: Intake Agent and Chief Editor already own intake and routing.
  - Expand only the Preflight Gate.
    - Rejected provisionally: preflight owns sufficiency to start, while S5.R4
      must also recognize task nature and likely needs; research will test the
      narrowest non-duplicative relation.
- Writer/implementation contract:
  - Result type: bounded canonical guidance, existing role/review consequences,
    ten-case validation, release documentation, state sync, and memory sync if
    material.
  - Reader path: request evidence -> recognition signals -> advisory need view
    -> Chief Editor challenge/decision -> existing activation and depth owners.
  - Must include: task type, likely capabilities/packs, research/review/evidence
    depth, significance signals, risk, ambiguity, decomposition, uncertainty,
    negative evidence, multi-task detection, and decision separation.
  - Must not include: scores, thresholds, automatic routing/activation/depth,
    new roles/pipelines/stages/gates, autonomous planning, or keyword-only
    inference.
  - Source boundary: authoritative external practice plus current repository
    canon; repository-specific choices remain explicit synthesis.
- Review focus: owner separation, recommendation/decision distinction,
  proportionality, contradictory and negative signals, simple-task protection,
  multi-domain/decomposition behavior, evidence traceability, no automation,
  state, memory, and all scenarios.
- Reroute triggers: safe behavior requires automation authority, a new owner,
  a duplicate preflight/routing system, or architecture outside mission scope.

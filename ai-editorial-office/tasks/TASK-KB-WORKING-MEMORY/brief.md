# Brief

Task ID: `TASK-KB-WORKING-MEMORY`
Date: 2026-07-02

## User Goal

Turn the AI Software Studio Knowledge Base from a passive knowledge store into working memory that records how knowledge is used inside the Studio.

## Required Outcomes

- Develop a knowledge application model.
- Extend the KB schema without disrupting the existing structure.
- Define a knowledge lifecycle with statuses and allowed transitions.
- Define how KB records link to Studio objects: roles, processes, artifacts, documents, BRD, rules, projects, governance, and Project State.
- Support applied, not-yet-applied, under-evaluation, deprecated, and rejected knowledge.
- Define Knowledge Coverage.
- Update representative existing records to demonstrate the new model.
- Prepare recommendations for future KB development and use by BRD, Product Analyst, Validator, and Historian.
- Verify documentation consistency.

## Explicit Constraints

- Do not change the existing KB structure without strong reason.
- Do not reduce record readability.
- Do not turn the KB into a development journal.
- Historian remains responsible for implementation history.
- KB describes knowledge and current application, not change chronology.

## Required Local Context to Study

- Current KB structure, schema, navigation, index, source register.
- Existing KB record types.
- `AGENTS.md`.
- `project-state.md`.
- Artifact templates.
- BRD Governance and Historian materials, if present.

## Source Boundary

Only local repository materials are required. No web research is needed for this task.

# Brief

## task title

Подготовить бизнес-требования к дашборду "Путешествия и хобби сотрудников УЭК".

## user goal

Создать редакционную задачу в `/tasks` и подготовить основной документ с бизнес-требованиями для нового функционала внутреннего портала УЭК.

## audience

Бизнес-заказчики, команда разработки, HR, внутренние коммуникации, модераторы и администраторы внутреннего портала.

## deliverable

Основной документ `business_requirements.md` на русском языке в формате пользовательских историй с acceptance criteria в формате Given / When / Then.

## channel or publication context

Внутренняя проектная документация для последующей продуктовой и разработческой работы.

## scope

В документе должны быть описаны:

- бизнес-контекст;
- цели;
- роли пользователей продукта;
- общая концепция дашборда;
- источники данных;
- настройки видимости;
- модерация;
- модуль "Карта путешествий";
- модуль "Хобби и увлечения";
- модуль "Календарь событий";
- аналитика;
- общие бизнес-правила;
- out of scope;
- открытые вопросы.

## constraints

- `AGENTS.md` остается canonical.
- Не менять системные правила ИИ-редакции, роли, review-gate и пайплайны.
- Работать как с обычной редакционной задачей внутри `/tasks`.
- Не менять production-файлы проекта без необходимости.
- Не использовать direct path `PDF -> SVG/PNG/MD`.
- Не добавлять техническую архитектуру, API, схемы БД, SSO, детальные интеграции, UX-тексты, макеты, сроки и оценки.
- Не делить требования на MVP / Phase 2.
- Не использовать приоритеты P1/P2/P3.

## client profile

Не активирован. Задача относится к УЭК и не является Sber-owned, Sber-product, Sber-communication или явной Sber-redpolicy задачей.

## source materials

Используются входные данные пользователя в текущем запросе: бизнес-обоснование, назначение функционала, аудитория, роли продукта, описание трех модулей, правила публикации и видимости, модерация, аналитика, формат документа и критерии готовности.

## factual sensitivity

Низкая. Документ формулирует целевую картину бизнес-требований на основе предоставленного брифа; внешние источники и проверка фактов не требуются.

## risk mode

Low-risk with review required.

## success criteria

- Создана task folder в `/tasks`.
- Заполнены необходимые task artifacts.
- Основной документ с БТ написан на русском языке.
- Документ написан в продуктовом стиле.
- БТ представлены через пользовательские истории.
- У пользовательских историй есть acceptance criteria Given / When / Then.
- Покрыты три модуля, роли, настройки видимости, модерация, аналитика, бизнес-правила, out of scope и открытые вопросы.
- Нет технической архитектуры, API, схем БД, UX-текстов и макетов.
- Review-gate не нарушен.
- `AGENTS.md` и production-файлы не изменены.

## open questions

Открытые вопросы должны быть вынесены в основной документ как вопросы для дальнейшего уточнения, а не как скрытые требования.

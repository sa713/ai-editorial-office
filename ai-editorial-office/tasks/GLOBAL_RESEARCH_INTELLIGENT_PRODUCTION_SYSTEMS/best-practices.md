## Cross-Domain Best Practices

| Practice / pattern | Why it matters | KB record |
| --- | --- | --- |
| Design production systems sociotechnically | Prevents tool-only optimization | `principle-sociotechnical-production-system` |
| Shorten feedback loops | Accelerates learning and risk detection | `principle-fast-feedback-loops` |
| Build quality into the workflow | Reduces late rework and inspection dependency | `principle-built-in-quality` |
| Use small batches | Improves flow and reviewability | `pattern-small-batches` |
| Maintain continuous delivery pipelines | Keeps releases repeatable and safer | `pattern-continuous-delivery-pipeline` |
| Use SLOs and error budgets | Makes reliability tradeoffs explicit | `pattern-slo-error-budget` |
| Treat platforms as products | Aligns shared capabilities with internal users | `pattern-platform-as-product` |
| Provide golden paths | Reduces cognitive load while preserving exceptions | `pattern-golden-paths` |
| Practice continuous discovery | Connects product work to customer evidence | `practice-continuous-discovery` |
| Use product trios | Reduces handoff loss across product/design/engineering | `pattern-product-trio` |
| Use opportunity solution trees | Links outcomes, opportunities, solutions, and experiments | `pattern-opportunity-solution-tree` |
| Run modern code review | Supports quality and knowledge sharing | `practice-modern-code-review` |
| Review architecture by viewpoints | Connects architecture to stakeholder concerns | `practice-architecture-review-by-viewpoints` |
| Integrate secure SDLC practices | Moves security into the development lifecycle | `practice-secure-sdlc-ssdf` |
| Build AI evaluation harnesses | Replaces demos with repeatable evidence | `practice-ai-evaluation-harness` |
| Manage AI context and memory | Prevents stale or unsafe AI context | `practice-context-and-memory-management` |
| Use human-AI checkpoints | Adds meaningful control where AI risk is high | `pattern-human-ai-checkpoints` |
| Keep ADR decision logs | Preserves rationale and consequences | `pattern-adr-decision-log` |
| Link knowledge to provenance | Makes KB records auditable and reusable | `pattern-provenance-linked-knowledge` |
| Use pause-point checklists | Reduces omissions in high-risk work | `practice-checklists-at-pause-points` |

## Conditions for Success

- Practices must be tied to real decisions and outcomes.
- Measurements must be balanced and context-aware.
- Standards must be tailored to risk.
- AI autonomy must be earned through evals.
- KB records must be maintained, not merely created.

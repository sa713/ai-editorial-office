# Compactness Risk Review

## Main Risk

The system can now be too compact in the wrong hands.

The rules say compact is bounded, but the failure mode is practical:

- fewer files can become less thinking;
- optional can become avoided;
- manifest can become overloaded;
- review can become a short approval note.

## Dangerous Compactness Zones

- weak or ambiguous brief;
- factual or product claims;
- external publication;
- source-sensitive material;
- diagnostic or author-facing analysis;
- multiple versions;
- unresolved contradictions;
- reviewer uncertainty;
- human approval complexity.

## Where Expanded Path Is Still Needed

- high-governance;
- conflict-heavy tasks;
- evidence-heavy tasks;
- version conflict;
- source dispute;
- stakeholder risk;
- unclear restart state;
- review outcome not confidently reproducible.

## Under-Documentation Risk

Compact finalization can skip finalization notes/checklist/handoff. This is safe
only when:

- `review.md` is clear;
- `final.md` changed nothing material beyond approved scope;
- `task-manifest.md` is current;
- `final_decision.md` records compact omissions.

If any of those fail, compact finalization becomes fragile.

## Net Assessment

Compactness is safe as written, but easy to abuse operationally. The system must
watch for shallow review and stale manifests.

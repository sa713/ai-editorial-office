# Rejected or deferred changes

## New behavioral agent

**Why not now**
TASK-0009 does not show a role gap. It shows a writing/review sensitivity gap.

**Return condition**
Only after repeated production failures that existing writer/reviewer roles cannot handle.

## Onboarding strategist

**Why not now**
Would turn a small editorial check into a new specialization.

**Return condition**
Only if the system later owns large onboarding programs, which is outside this iteration.

## Persuasion system

**Why not now**
The goal is reduced friction, not influence optimization.

**Return condition**
No current return condition. This conflicts with governance intent.

## Emotional scoring

**Why not now**
Scores would create false precision and behavioral ambition.

**Return condition**
Only with explicit human mandate and strong evidence need; not for iteration 002.

## Adoption metrics

**Why not now**
Would move the work from editorial quality to adoption management.

**Return condition**
Only if a separate product analytics mandate exists.

## Engagement optimization

**Why not now**
Conflicts with usefulness-first editorial work.

**Return condition**
Not for the editorial core.

## Conversion funnel

**Why not now**
Not relevant to internal editorial clarity.

**Return condition**
Only in a separate marketing/product system, not here.

## Behavioral dashboard

**Why not now**
No measurement model, no production evidence, high bloat risk.

**Return condition**
Only after repeated validated need for reporting, and outside this iteration.

## Automatic pressure detector

**Why not now**
Would add automation before the rule is proven in production.

**Return condition**
Only after manual review patterns are stable and repeated.

## Mandatory reader-state block for every task

**Why not now**
Most tasks do not need it. It would add ritual overhead.

**Return condition**
Never as a universal default. Could become required only for a clearly defined task type.

## Rewrite of all pipelines

**Why not now**
Implementation should start in editorial knowledge, not pipeline redesign.

**Return condition**
Only after 5-10 production tasks show the same pipeline-level gap.

## Full migration of old tasks

**Why not now**
Legacy artifacts are historical evidence, not material to retrofit.

**Return condition**
Only if old task reuse creates active production confusion.

## Tone-policing layer

**Why not now**
The issue is reader action friction, not taste.

**Return condition**
No return condition. Review should stay tied to concrete reader outcome.

## Social-proof strategy

**Why not now**
High risk of unverified claims and adoption pressure.

**Return condition**
Only when social proof is factual, sourced and explicitly requested by the human owner.
